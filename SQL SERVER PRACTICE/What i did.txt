Database console commands or DBCC are T-SQL Commands grouped in to four 
categories, Maintenance, Miscellaneous, informational and validation.
DBCC commands are used to see running processes on your server

It is used to perform consistency check for a table/catalog for a

	DBCC CHECKALLOC
It is used to check page usage and allocation of a database.
	DBCC CHECKTABLE(tablename)
It is used to verify data page integrity, page offsets, data page links,
page pointers, index pointers, index sort order for a specified table.
	DBCC SQLPERF(logspace)

	DBCC SHOWFILESTATS

	DBCC CHECKIDENT(tablename)
It is used to check identity information or to return current identity 
value for a particular table.
	DBCC TRACEOFF

	DBCC TRACEON
It is used to enable tracing.

release the free space to OS.
	DBCC SHRINKFILE(file_id)

	MERGE statement used in SQL? 
To help with performance because it is a combination INSERT UPDATE AND 
DELETE performing these scripts over and over can slow performance
Write a query to illustrate the use of MERGE
MERGE INTO bonuses D
   USING (SELECT employee_id, salary, department_id FROM employees
   WHERE department_id = 80) S
   ON (D.employee_id = S.employee_id)
   WHEN MATCHED THEN UPDATE SET D.bonus = D.bonus + S.salary*.01
     DELETE WHERE (S.salary > 8000)
   WHEN NOT MATCHED THEN INSERT (D.employee_id, D.bonus)
     VALUES (S.employee_id, S.salary*0.1)
     WHERE (S.salary <= 8000);

	Index key column 
This is the column used in the index, and used by the optimizer to 
decide which  of the index is applicable. It's also used by
the execution engine to fulfill the WHERE part of the query. This is 
equivalent to the stuff in the back of a book. It is used for the SELECT
part of the query if the column is needed.

	Included column 
This is added to the index, not used by the optimizer or execution engine
in finding the rows or joining tables. It can only be used by the SELECT
part of the query to return the data.

There is no point in having a key column included separately. It's 
already in the index as a key column and if it were INCLUDED, you would 
be storing it twice. I'm not positive that SQL would do this and I would
hope the engine would be smart enough to not duplicate it.
